# Визуальный редактор сюжета

Патч устанавливается поверх zombie_episode2_complete.patch.
Откройте проект в Godot 4.6+ и вкладку **Сюжет → Эпизоды** сверху.
Если вкладки нет, включите **Dialogue Nodes** в Project Settings → Plugins.
Во второй вкладке **Диалоги Dialogue Nodes** доступен исходный редактор .tres.

## Источник игровых данных

Игра загружает `data/story_graphs/episode1.json` и `episode2.json`.
Оба эпизода перенесены без изменения идентификаторов сцен и содержания.
Старые opening.json / city_routes.json / episode*_routes.json оставлены как
архив переноса из Flash; игра их больше не загружает. Редактировать нужно графы.
**Не запускайте migrate_story_graph.py поверх отредактированного графа:** это
одноразовый инструмент восстановления из архивных данных.

Выберите эпизод слева сверху. Поиск справа ищет по ID и тексту; щелчок
переносит камеру к блоку. Колесо меняет масштаб, средняя кнопка перемещает поле.
Мини-карта показывает весь эпизод. Кнопка «Разложить» выстраивает блоки по
расстоянию от начала; позиции сохраняются вместе с графом.

## Блоки и связи

* **Сцена** содержит фон, текст, звук, оригинальные координаты/маски и режим
  экрана: обычный, выбор, автоматический переход, предмет, смерть или спасение.
* **Ответ** содержит текст ответа. «Далее» ведёт в следующую сцену.
* **Действие** содержит назначение переменных и прибавление/вычитание значений.
  Связь «Последствия» применяется при выборе ответа, «При входе» — при входе
  в сцену. Это связи принадлежности, а не дополнительный экран для игрока.
* **Условие** задаёт доступность ответа или переопределяет переход. Все строки
  одной проверки соединяются логическим И. Поддержаны равенство, нижняя и
  верхняя границы, диапазон. «Если 1», «Если 2» проверяются по порядку;
  при отсутствии совпадений используется «Далее».
* **Реплика** показывает персонажа и текст, затем связанные ответы.
* **Ввод кода** ждёт ввода, проверяет переменную с правильным кодом и считает
  ошибки. Ответ 1 — правильный код; ответ 2 — попытки исчерпаны. Обычная ошибка
  оставляет игрока на той же сцене. Можно задать код со знаками `*` и `#`.
* **QTE** задаёт время, число нажатий и неподвижную/случайную цель.
  Ответ 1 — число нажатий достигнуто; ответ 2 — время истекло.
  Куда вести каждый результат, решает автор: первый выход может вести к смерти.

Для создания ветки нажмите «Добавить ответ / результат» в инспекторе сцены,
затем соедините выход «Далее» ответа со входом следующей сцены.
У ответа есть кнопки добавления последствий, условия доступности и условного
перехода. Условие доступности скрывает ответ, когда проверка не пройдена.
Варианты текста/звука существующих сцен показаны отдельными блоками условий.
Их дополнительные свойства доступны в секции JSON; обычные тексты, переменные,
числа и ресурсы редактируются полями без JSON.

Смена связей, создание/удаление/дублирование и редактирование поддерживают
отмену/повтор. Ctrl+S сохраняет, Ctrl+Z отменяет, Ctrl+Y повторяет.
Неверные типы связей отклоняются; проверка перед сохранением выявляет оборванные
переходы, отсутствующее начало, пропавшие ресурсы и циклы автоматического
получения предметов. Незавершённый граф сохраняется в файл `.json.draft`:
игра продолжает использовать предыдущий завершённый вариант. Такой черновик
можно открыть кнопкой «Открыть…»; после устранения ошибок «Сохранить» обновит
основной граф.

## Тестирование

Выберите сцену и нажмите «Тест с блока». Текстовый симулятор позволяет задать
флаги и пройти ветки, код и QTE; выбранный блок подсвечивается, внизу видна
история переходов и текущие переменные. Он использует отдельное сохранение
и не меняет прохождение игрока. Симулятор проверяет логику; оформление, звук и
расположение случайной QTE-цели проверяйте запуском игры.

Пример: откройте `data/story_graphs/examples/activity_demo.json` и запустите
тест. Последовательность: реплика → ввод *123# → пять нажатий за четыре секунды
→ результат. Начальные переменные примера загружаются автоматически.

## Следующий эпизод

«Новый эпизод» создаёт граф с выбранным номером от 3. В «Параметрах» задаются
название, описание и начальные переменные; начальную сцену можно назначить
в её инспекторе. Новый файл `data/story_graphs/episodeN.json` автоматически
подключается к игре при следующем запуске, открывает соответствующий пункт
меню (либо добавляет новый), получает собственную статистику.
Действия, ресурсы, диалоги и активности добавляются кнопкой «+ Блок».
Для оформления новой сцены выбирайте фон и звук через кнопки выбора ресурсов.

Оригинальные Flash-анимации и конкретные активности поздних эпизодов этим
патчем не переносятся: здесь подготовлены редактируемые блоки и их исполнение.
QTE поддерживает общее время и число попаданий; отдельные временные окна каждой
цели из поздних Flash-сцен потребуют расширения этого типа при их переносе.

## Проверки

```
godot --headless --path . --script tools/story_graph_test.gd
godot --headless --path . --script tools/story_activity_test.gd
godot --headless --path . --script tools/episode1_test.gd
godot --headless --path . --script tools/episode2_test.gd
```

Сохранения сохраняют старые ID и совместимы с предыдущим патчем. Состояние
ввода кода/QTE сохраняется; пауза останавливает таймер QTE.
