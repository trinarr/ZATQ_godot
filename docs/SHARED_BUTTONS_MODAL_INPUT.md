# Общие кнопки и модальный ввод

Правка подготовлена поверх `zombie_pause_components.patch` на исходниках
`a92c583`. Применение из корня проекта:

```bash
git apply --check zombie_shared_buttons_dialog.patch
git apply zombie_shared_buttons_dialog.patch
```

## Два рваных компонента

- `scenes/shared/TornTextButton.tscn` — Button с собственной шейдерной подложкой
  и дочерней Label. `caption_key`, `caption_font`, `caption_size` доступны
  в инспекторе; `set_caption()` разрешает локаль и подбирает размер текста.
- `scenes/shared/TornIconButton.tscn` — квадратный Button с такой же подложкой
  и дочерними TextureRect. `icon_texture` принимает обычную текстуру или атлас.

Оба наследуют общие обработку ввода, состояния и шейдер. Материал у каждого
экземпляра независимый. Значки и текст не обрабатывают касания.

Переведены главное меню и продолжение игры, все экраны выбора эпизодов/тестов,
справка, пауза, подбор предметов, результаты и переход к следующему эпизоду,
подтверждения, ввод кода и рваные ответы собеседников. Исходные координаты,
цвета и PNG используются повторно. Справка использует AtlasTexture с областями
существующего общего листа значков: новый дублирующий PNG не создаётся.

## Диалог выбора из Flash

`NewItem` использует `Symbol 99` и четыре `Symbol 97`. Подложка ответа —
металлический `Symbol 93 / Bitmap 91`, а не рваная кисть. Текст `Txt` находится
внутри соответствующей кнопки. Неиспользуемые слоты переходят на шестой кадр
и показывают `Bitmap 95` со знаком запрета.

`dialog_answer_button.gd` повторяет эту структуру: Button, исходная подложка,
дочерняя Label; недоступный слот — затемнённая подложка и исходный знак запрета.
Одна PNG подложки переиспользуется всеми ответами во всех эпизодах.
`choice_buttons` содержит только активные варианты, сохраняя индексы решений;
`answer_slots` включает четыре слота. Металлические ответы больше не рисуются
рваным шейдером. Ответы `DialogMov` с широкой серой кистью используют
TornTextButton с исходным цветом и принадлежащим кнопке текстом.

Пересборка новых деталей из исходного архива:

```bash
python tools/build_dialog_components.py original.zip
```

## Защита попапов

ModalView имеет общий блокировщик ввода размером с видимую безопасную область,
в том числе для окон без визуального затемнения. Щелчки, касания и прокрутка
не проходят к игровым элементам. Если хост добавляет игровой элемент после
попапа, модальное окно остаётся выше него. Вложенные попапы блокируют предыдущие,
а после закрытия возвращают им ввод. Для разрешённого закрытия по фону
обрабатывается касание самого затемнения.

## Проверки

`modal_buttons_test.gd` посылает реальные GUI-события мыши и эмулированные
касания: сначала доказывает, что нижняя кнопка реагирует без попапа, затем
проверяет блокировку, поздно добавленные элементы, вложенные окна, рабочие
ответы и неизменность положения подписей. Также проверяются самостоятельные
компоненты, все 12 селекторов и оригинальный цвет ответов собеседника.

Дополнительно проходят `shared_menus_test.gd`, `shader_buttons_test.gd`,
`ui_components_test.gd`, `pause_menu_test.gd`, `opening_layout_test.gd`,
`result_ui_test.gd`, проверки компонентов всех трёх эпизодов и аудит ресурсов.
Проверки выполнены в Godot 4.6.1 headless; аппаратный рендеринг на Android
в этой среде не проверялся.
