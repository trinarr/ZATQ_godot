# Технические проверки ZATQ

Команды выполнять из корня проекта. Выбирать проверки по изменённой области; полный прогон не требуется для каждой локальной правки. Этот документ описывает порядок работы, а не отчёт об успешном прогоне. [TESTS.md](TESTS.md) описывает игровые викторины.

## Python-проверки

`python` означает доступный Python 3. В ряде инструментов используется `Path.read_text()` без явной кодировки, поэтому на Windows запускать в режиме UTF-8:

```powershell
python -X utf8 tools/verify_content.py
python -X utf8 tools/verify_locales.py
python -X utf8 tools/audit_resources.py
```

Это проверки ссылок контента, локализаций и использования ресурсов. Аудит ресурсов учитывает отслеживаемые Git-файлы и известные способы динамической загрузки; его список кандидатов не является разрешением на удаление.

Не запускать `build_*`, миграторы, нормализаторы или исправляющие инструменты вместо проверок. Перед незнакомым инструментом прочитать его код и, если поддерживается, `--help`: наличие слова `test` или `verify` не заменяет проверки побочных эффектов.

## Изоляция Godot-проверок

Для проверки локализации есть специальный изолированный запускатель:

```powershell
python -X utf8 tools/localization_export_test.py --godot 'C:/path/to/Godot.exe'
```

Он создаёт минимальный временный проект без игровых autoload, импортирует таблицы и проверяет все существующие переводы в PCK без CSV. `--ui` добавляет GPU-проверки телевизионных экранов и снимки RU/EN. Профили редактора перенаправляются во временный каталог. Этот запускатель не предназначен для тестов состояния `Quest` и не заменяет их изоляцию, описанную ниже.

До запуска сцен и скриптов с игровыми autoload обеспечить отдельный тестовый каталог пользовательских данных. Само копирование проекта не изолирует `user://`: он зависит от настроек приложения. Переменная `XDG_DATA_HOME` из Linux-примеров не доказывает изоляцию на Windows.

Временная копия проекта с отдельными `application/config/use_custom_user_dir` и `application/config/custom_user_dir` может использоваться для изоляции. Настройки менять только в тестовой копии. До запуска игровых autoload подтвердить фактический `OS.get_user_data_dir()` отдельным минимальным проектом с теми же настройками приложения, без игровых autoload; каталог должен быть временным, отличаться от профиля игрока и не содержать его сохранений. При неподтверждённой изоляции не запускать игровые проверки.

Некоторые существующие тесты меняют `Quest.save_path`, `tmp_path` и `backup_path` после старта. Это полезно для тестовых файлов, но не изолирует первоначальную загрузку: `Quest._ready()` уже читает сохранение, а восстановление прогресса может вызвать запись результата. Поэтому переименование файлов внутри теста не заменяет изоляцию профиля до старта процесса. Общего проверенного запускателя с такой защитой в текущем проекте нет.

## Godot: порядок запуска

Использовать движок, совместимый с `project.godot`. Сначала выполнить импорт ресурсов выбранным движком. Следующие примеры применимы только после подготовки изолированной тестовой копии; `$testProject` должен указывать на её абсолютный путь, а `godot` — на установленный движок:

```powershell
godot --headless --path $testProject --editor --import
godot --headless --path $testProject --script tools/smoke_test.gd
```

Проверять код возврата, итоговый отчёт и отсутствие `ERROR` / `SCRIPT ERROR`. Предупреждения об утечках фиксировать отдельно. Успех выбранных сценариев не означает успешный полный прогон или проверку Android.

## Выбор сценариев

Пути ниже существуют в репозитории; это отправные точки, а не исчерпывающий набор. Перед запуском читать затронутый тест и его зависимости. Godot-скрипты запускаются аналогично примеру выше через `--script`.

| Изменение | Подходящие проверки |
| --- | --- |
| Графы, сюжетные условия, переходы | `tools/verify_content.py`, `tools/story_graph_test.gd`, `tools/episode1_test.gd` … `tools/episode6_test.gd` для затронутого эпизода |
| Сохранения и результаты | `tools/smoke_test.gd`, затронутые проверки эпизодов; отдельно восстановление, совместимость ID, повторная запись результата и прерванная запись |
| Локализация | `tools/verify_locales.py`, `tools/localization_test.gd`; для соответствующего контента `tools/john_export_localization_test.gd`, `tools/episode6_export_localization_test.gd` |
| Адаптация, хитбоксы и подсветки | `tools/safe_area_test.gd`, `tools/world_alignment_test.gd`, `tools/episode_hotspot_bounds_test.gd`, затронутые `tools/episode1_highlights_test.gd` / `tools/episode23_highlights_test.gd` |
| Общие окна и ввод | `tools/shared_menus_test.gd`, `tools/modal_buttons_test.gd`, `tools/pause_menu_test.gd`, сценарий конкретного окна |
| Таймлайны, QTE, пауза | `tools/flash_playback_clock_test.gd`, `tools/episode_pause_policy_test.gd`, `tools/qte_prompt_test.gd`, соответствующий тест анимации или перехода |
| Шрифты, прозрачность, тени, шейдеры | `tools/shader_buttons_test.gd`, `tools/modal_shadow_regression_test.gd`, соответствующий UI-сценарий и визуальная проверка на GPU |
| Ресурсы, компоненты арта | `tools/audit_resources.py`, `tools/verify_content.py`, затронутые проверки компонентов и визуальное сравнение в игре |
| Игровые викторины | `tools/quiz_source_test.py`, `tools/quiz_content_test.gd`; описание контента — в `docs/TESTS.md` |
| Runtime-оптимизация | `tools/runtime_optimization_test.gd`, проверки затронутых потребителей |

`tools/export_pack_ui_test.gd` имеет особый контракт: запуск против экспортированного PCK без исходных `locales/*.csv`, из каталога вне проекта. Это не обычная проверка через `--path` исходного дерева. Перед использованием прочитать заголовок скрипта; профиль экспорта тоже должен быть изолирован.

Если существующий сценарий не покрывает обнаруженный риск, добавить адресную регрессию. Не считать перечисление проверки доказательством, что она уже покрывает все случаи строки таблицы.

## Визуальная проверка

Headless проверяет логику и геометрию, но не подтверждает внешний вид, смешивание альфы, читаемость и плавность. Для UI, шрифтов, шейдеров и анимаций нужен запуск с GPU.

- Базовый размер: 1600×960. Широкий: 2400×1080. При изменении адаптации дополнительно 1280×960; для safe area — 2048×920 с асимметричным отступом. Эти размеры используются существующими проверками раскладки и совмещения.
- Проверять RU и EN, включая существующий fallback; это не разрешает дописывать переводы нарратива.
- Проверять повторное открытие/закрытие, быстрые нажатия, промежуточную прозрачность, полное исчезновение и восстановление элемента, остановку и повторный запуск анимации, завершение callbacks после ухода с экрана.
- Сопоставлять видимый объект с хитбоксом, маской и подсветкой после изменения окна и safe area. Проверять читаемость с повествованием и открытыми окнами.
- Для таймлайнов и QTE проверять паузу и возобновление, прерывание и однократность перехода. Учитывать различие ожидания первого кадра в headless и при реальном рендеринге.
- Для арта дополнительно соблюдать визуальную проверку из [ZATQ_ART_STYLE.md](../ZATQ_ART_STYLE.md).

Проверку на Android-устройстве и проверку экспортированной сборки указывать отдельно от desktop-прогона. Для документационных изменений достаточно проверки ссылок и `git diff --check`.
